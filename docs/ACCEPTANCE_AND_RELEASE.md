# Приёмка, пилот и подача продукта

**Статус: шаблоны подробной приёмки.** Для выпуска 1.5.3 Azmail 12 ноября 2026 года подтвердил успешный игровой прогон; отдельные строки матрицы не заполнялись.

База: 1.5.2, commit `9c5fee6e7ee2677c062b580e78b54546bee7247a`. Подготовлено 11 ноября 2026 года.

Навигация: [Стратегия](PRODUCT_STRATEGY.md) · [Контракт платформы](PLATFORM_SPEC.md) · [README](../README.md).

## 1. Что считается доказательством

Разделять четыре уровня:

1. **Есть в исходниках:** найден реальный путь от входа до результата.
2. **Проверено локально:** отработал тест на заглушках; это не запуск ESO.
3. **Проверено в игре:** записаны версии, сценарий, результат и наблюдаемое действие.
4. **Подтверждено пользователями:** независимый игрок повторяет сценарий в своей обычной сборке.

Историческая база 1.5.2: локальные regression-проверки с ESO/TTC stubs проходили; внутриигровая приёмка ещё не выполнена. При подготовке этих документов Lua-код не менялся, игра не запускалась, новые возможности не реализовывались.

## 2. Карточка игрового прогона

Заполняется перед проверкой, неизвестные поля не угадывать:

| Поле | Значение |
|---|---|
| Дата, проверяющий | Не заполнено |
| ESO PC: Live/PTS, версия клиента и UI API | Не заполнено |
| Версия / commit bridge | Не заполнено |
| LibCustomMenu, LibAddonMenu и TTC / дата ценовых данных | Не заполнено; отсутствующие optional-зависимости отметить |
| Сторонний addon и конкретная команда | Не выбран; поддержка не подтверждена |
| Другие модификации gamepad inventory/UI | Не заполнено |
| Язык UI, разрешение и масштаб | Не заполнено |
| Набор включённых optional-функций bridge | Не заполнено |
| Ссылка на issue / безопасное evidence | Не заполнено |

Не нужен отдельный игровой стенд для каждой мелочи. Первый прогон — на существующей домашней установке с понятной конфигурацией. Несовместимость исследуется отдельно по фактическому симптому. Не выполнять продажу, удаление, покупку или другую труднообратимую операцию ради демонстрации без отдельного согласования; использовать безопасное действие и тестовый предмет, где возможно.

## 3. Матрица базовой приёмки

Все строки ниже изначально **NOT RUN**. Для каждой поставить `PASS`, `FAIL` или `N/A` с причиной. Отсутствие подходящего стороннего аддона — блокер проверки интеграции, а не `PASS`.

| ID | Сценарий | Наблюдаемый результат | Когда обязателен |
|---|---|---|---|
| G-01 | Открыть персонажа и inventory в gamepad mode | Нет новых ошибок загрузки; native actions доступны | Для первого игрового пилота |
| G-02 | Выполнить безопасное действие конкретного LibCustomMenu-аддона | Изменился именно выбранный предмет; действие сработало один раз | Для заявления о поддержке этого сочетания |
| G-03 | Проверить parent, child и checkbox на контролируемом меню | Независимая семантика; ребёнок не запускает parent; toggle меняет ожидаемое состояние | При приёмке соответствующих типов меню |
| G-04 | Переместить выбор между предметами и закрыть inventory при обновлении overlay | Нет данных прошлого предмета и всплытия закрытого overlay | Для включённого overlay |
| G-05 | Проверить «в хлам / убрать из хлама» на подходящем предмете | Состояние меняется предсказуемо, без второго дубля команды | Для обещания native junk fallback |
| G-06 | Проверить отсутствие optional TTC и LibAddonMenu | При наличии обязательного LibCustomMenu базовые actions продолжают работать; недоступная информация не ломает меню | Для заявления о независимости actions от optional-интеграций |
| G-07 | Проверить TTC с ценой, без цены и с неизвестной актуальностью | Нет выдуманных цен; доступная давность понятна, неизвестная не выдаётся за свежую | Для ценовой функции; улучшения UX без реализации записать как backlog |
| G-08 | Открыть поддерживаемый crafting-сценарий с полными и неполными ценами; отдельно рецепт с большим списком | Общая оценка учитывает весь известный состав; неполнота обозначена, сравнение не выдано за прибыль | Для соответствующей crafting-функции |
| G-09 | Проверить торговый лот и количество в стопке | Сопоставлен конкретный выбранный лот; цена штуки не перепутана со стоимостью стопки | Для заявления о торговом сравнении |
| G-10 | Переключить keyboard/gamepad и проверить исходный путь аддона | Нет потери исходных действий и новых повторных вызовов | Для baseline совместимости |
| G-11 | Повторить целевой сценарий с конкретной крупной UI-модификацией | Нет дублей и конфликтов навигации в записанных версиях | Только если заявляем поддержку этой комбинации |

Разрешение/масштаб дополнительно проверять, если проблема касается layout или расширяется поддерживаемый диапазон. Не вводить полный регресс всех окон и всех аддонов для каждой документационной или локальной обратимой правки.

## 4. Приёмка нового API — отдельный этап

Только после реализации [PLATFORM_SPEC](PLATFORM_SPEC.md):

- Provider зарегистрирован, действие появилось и выполнилось в игре.
- На неподходящем предмете действие отсутствует либо объяснимо недоступно.
- Callback error, unregister и смена предмета не исполняют старое действие.
- Два providers не ломают друг друга, включая одинаковые labels с разными IDs.
- Legacy-подключение работает без изменения старого callback contract.
- Пример устанавливается по своей инструкции и использует только публичный API.
- Пилотный внешний автор повторяет интеграцию без доступа к private-функциям.

Подробные автоматизируемые критерии находятся в спецификации, здесь фиксируется наблюдаемый игровой результат. Синтетические providers полезны для управления условиями ошибки, но не считаются двумя внешними интеграциями.

## 5. Проверки для разработчика

Для **изменения кода** использовать релевантные проверки проекта:

- `lua scripts/tests/regression.lua` — текущий regression harness.
- `lua5.1 scripts/tests/regression.lua` — проверка на Lua 5.1, если этот интерпретатор доступен.
- Синтаксис изменённых Lua-файлов и `git diff --check`.
- При изменении упаковки — штатная сборка `bash scripts/build_release.sh`, CRC, install-folder layout, версии, отсутствие лишнего и соответствие упакованного кода проверенному исходнику.

Не выдавать отсутствие интерпретатора или пропущенный тест за `PASS`. Не запускать чужие материалы из `tests/` как доказательство качества ESO-аддона: текущий проверочный entry point — [scripts/tests/regression.lua](../scripts/tests/regression.lua).

Для **документационной правки**, как эта, достаточно ссылок, согласованности статусов и diff-проверки. Она не требует пересборки релиза или повторного игрового прогона.

## 6. Короткая диагностика для сообщения об ошибке

Команды уже реализованы в 1.5.2: [источник](../LibGamepadContextMenuBridge/LibGamepadContextMenuBridge.lua#L3614).

1. Записать версии и ожидаемое действие.
2. Посмотреть `/lgcmb status`.
3. Для конкретного воспроизведения включить `/lgcmb debug on`; verbose включать только при необходимости.
4. Выполнить один проблемный сценарий, посмотреть `/lgcmb log 60`.
5. Выключить `/lgcmb debug off` и, если включали, `/lgcmb verbose off`.

Перед публикацией вручную убрать account/character names, приватный чат, торговые данные и прочую личную информацию. Не прикладывать весь SavedVariables или весь пользовательский AddOns-каталог. Для диагностики обычно нужны короткий обезличенный фрагмент и последовательность действий, а не дамп окружения.

### Шаблон issue

- Версии ESO / bridge / LibCustomMenu и затронутого аддона:
- Контекст и тип предмета:
- Ожидал:
- Получил:
- Минимальные шаги:
- Повторяется ли без optional overlay / с другим UI:
- Проверенный безопасный фрагмент диагностики или кадр:
- Временный обход, если известен:

Пустые ответы допустимы с пометкой «не проверял»; не требовать отключения всех аддонов без причины.

## 7. Пилот с игроками и авторами

1. Выбрать конкретный безопасный сценарий и соответствующий сторонний аддон.
2. Показать минимальную инструкцию, но не объяснять заранее каждый шаг.
3. Зафиксировать первый успешный результат, необходимость подсказки и фактические переключения на мышь.
4. Собрать добровольный отзыв после обычных сессий: оставил ли игрок аддон включённым, что стало проще, что мешает.
5. Внешнему автору дать пример и API reference; отметить места, где пришлось читать исходник или обращаться за помощью.
6. Исправить первое повторяющееся препятствие, а не расширять продукт случайными функциями.

Пороговые цели пилота описаны в [стратегии](PRODUCT_STRATEGY.md). Это не скрытая телеметрия: никакого сбора игровых действий или аккаунтов без отдельного согласия. До появления результатов не утверждать, что удержание или спрос доказаны.

| Блок | Содержание | Основание |

## 9. Условия выпуска и остановки

### Обычный patch

Есть точечная цель, релевантные проверки и отсутствие известной регрессии затронутого пути. Не нужно заново собирать пять тестеров или две внешние интеграции для каждого исправления.

### Первый рекомендованный игрокам вариант

Пройден обязательный игровой сценарий, есть безопасная демонстрация и точные ограничения. Критические проблемы, влияющие на этот сценарий, закрыты. Пока этого нет — честное beta-позиционирование, а не «обязателен всем».

### Первый стабильный provider API

Пройдены критерии спецификации, пример действительно работает в игре и контракт испытан внешним автором. Для заявления об экосистеме нужны независимые интеграции, а не один локальный пример.

### Стоп выпуска

Действие применяется не к тому предмету, повторяется после ошибки, ломает native menu, создаёт необъяснимое выполнение после смены выбора либо обнаружено труднообратимое нежелательное действие. Исправление такого дефекта важнее новой функции.

### Откат

При игровом блокере отключить затронутую optional-функцию либо bridge через `/lgcmb off`; если это не восстанавливает работу — выключить аддон и перезагрузить UI штатным способом. Для переустановки использовать ранее опубликованную совместимую версию и записать её номер. Не удалять SavedVariables автоматически и не обещать откат изменённой схемы без проверки миграции.

## 10. Проверка публикации

- GitHub: нужные branch/tag указывают на проверенный commit, asset соответствует локальному ZIP.
- ESOUI: обновлена существующая страница `4432`, сохранены beta/channel и доказанные compatibility targets; новые targets не отмечены только ради снятия warning.
- После отправки прочитать состояние именно обновлённого аддона. `Pending` означает ожидание модерации, **не публичную доступность нового ZIP**.
- После одобрения скачать публичный архив и сравнить его с проверенным release artifact.
- Пока файл на модерации, не отправлять его повторно и не заявлять, что обновление уже доступно всем.

Статус публикации меняется со временем. Этот документ — процедура, а не живой мониторинг ESOUI.
